# 專案規則（AGENTS.md）

## 語言與風格
- 文件、commit 訊息、對使用者的回報：一律繁體中文，以白話為主。
- 程式碼註解只在必要時寫；不使用 emoji；不要留大段被註解掉的死程式碼。

## 流程
1. 需求變更 → 先更新 `docs/01-需求規格.md`，並取得使用者確認，才動工。
2. 一次只推進一個里程碑；任務卡在 `tasks/`。
3. 一個里程碑 → 一個 commit ＋ 一個 tag（`m1`、`m2`…），訊息格式 `M<n>: <白話摘要>`。
4. 動工前先讀 `docs/03-開發計畫.md` 與對應任務卡。

## 驗收
- 每個里程碑都要有「可執行的驗收條件」與實際輸出。
- 執行方式：`<指令>`（第一次有程式碼後補上）。
- 沒有驗證輸出，不得宣稱完成。

## 禁止
- 不提交金鑰、`.env`、`node_modules/`、`dist/`、`.artifacts/`。
- 未經使用者同意，不得 `git reset --hard`、`git push --force`、刪除資料夾或檔案。
- 不擅自安裝新套件或插件（先問使用者）。
- 不改動本專案範圍外的檔案。

## 給 subagent 的提醒
- 任務卡是自足規格；看不到母對話時，以任務卡與本檔為準。
- 回報格式：做了什麼／改了哪些檔案／怎麼驗證（貼實際指令與輸出）／殘留問題。
