# pm-handoff — 里程碑收尾、版控與白話回報

## 鐵則
1. **沒有驗收證據不得收尾**。驗收證據＝你實際執行的指令與輸出、或你讀過的檔案內容。
2. **一個里程碑一個 commit 加一個 tag**，訊息格式 `M<n>: <白話摘要>`。
3. commit 前必看 `git status`；不得提交金鑰、暫存檔、產物檔（`.env`、`node_modules/`、`dist/`、`.artifacts/`）。
4. 回滾指令必須寫給使用者（放在 `docs/04-進度日誌.md`），讓他隨時能回到上一個好版本。

## 步驟

### 1. 收尾前檢核
- [ ] 里程碑的驗收條件全部通過（有輸出為證）
- [ ] `git status --short` 的每一項變更都在預期內
- [ ] 沒有金鑰／大檔／暫存垃圾
- [ ] `README.md` 的「目前狀態」已更新成現在真的能做的事

### 2. commit
```powershell
cd '<專案路徑>'      # 該專案的資料夾（不是工作區根目錄）
git status --short
git add -A
git commit -m "M<n>: <白話摘要>" -m "變更：<主要檔案>\n驗證：<指令與結果>"
```

### 3. tag
```powershell
git tag m<n>
git log --oneline --decorate -5
```

### 4. 更新文件
- `docs/04-進度日誌.md` 追加一列：

```markdown
| 日期 | 里程碑 | 做了什麼（白話） | 驗證證據 | 回滾方式 | 下一步 |
|---|---|---|---|---|---|
| <YYYY-MM-DD> | M<n> | | `<指令>` → `<輸出摘要>` | `git reset --hard m<n-1>`（需同意）／`git checkout m<n-1> -- .` | |
```

- `CHANGELOG.md` 加一段 `## M<n> — <日期>` 與重點。
- `docs/05-驗收報告.md`（整個專案完成時）：
  專案目的、對照需求規格的逐條驗收結果、如何執行、已知限制、後續建議。

### 5. 交付給使用者
若產出是檔案（報告、文件、試算表、簡報），用 `present` 讓使用者能直接打開；
程式類專案則在回報中寫清楚「怎麼啟動」與「怎麼看結果」。

### 6. 白話回報（固定三句 ＋ 一句詢問）
```
已完成：<白話說明這次多做得到什麼>
證據：我跑了 <指令／測試>，結果 <一句話>；版本已存檔為 m<n>（要回復隨時可以）
下一步：<下一個里程碑要做的白話描述>
要我繼續嗎？（繼續（推薦）／先停／調整方向）
```

## 常見錯誤
- ❌ 一個里程碑拆成 5 個 commit → 使用者看不出對應關係；收成一個並在 body 列重點。
- ❌ tag 直接用手打錯字 → 每次用 `git tag m<n>`，並 `git log --decorate` 確認。
- ❌ 回報寫技術細節 → 改成白話；技術細節留給文件。
- ❌ 專案完成時沒寫驗收報告 → 使用者日後無從確認「當初要的功能都有了」。
