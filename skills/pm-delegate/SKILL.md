# pm-delegate — 派工、監督、獨立驗證

## 鐵則
1. **任務卡必須自足**：subagent 看不到本對話。目標、脈絡、寫入範圍、驗收條件、回報格式缺一不可。
2. **不採信 subagent 的自述**。一切以你自己看到的檔案內容、指令輸出、測試結果為證據。subagent 說「已完成」但檔案沒變 → 就是沒完成。
3. **寫入範圍不重疊**：同一檔案不得由兩個 subagent 同時寫；並行時先分配互斥的檔案範圍。
4. **重派上限 2 次**：同一任務連續失敗 3 次就停下來，用白話向使用者說明卡在哪、需要什麼決定。
5. 不做「順手的大重構」。範圍外的改動一律回報使用者，不擅自做。

## 步驟

### 1. 選擇工具
| 情境 | 用什麼 |
|---|---|
| 單一自足任務 | `subagent`（背景執行） |
| 多個互不影響的任務 | 同一則訊息**同時**啟動多個 `subagent` |
| 大型平行掃描／遷移／多角度查證 | `workflow`（**僅在使用者明確要求時**） |
| 需要延續同一脈絡的後續分析 | `subagent_fork` |

一次里程碑內同時最多 2～3 個 subagent。

### 2. 啟動（背景）
- 每個 subagent 附上完整任務卡內容（不要只給路徑；若卡已存檔，把內容貼進 prompt）。
- 明確禁止事項：不要動範圍外檔案、不要改資料格式、不要安裝新套件（除非卡片允許）。
- 要求回報格式：**做了什麼／改了哪些檔案（路徑）／怎麼驗證（貼指令與輸出）／殘留問題**。

### 3. 監督循環
1. `list_agents` 看狀態；需要等就用 `wait_agent`（不要在沒有其他成員在跑時空等）。
2. 不用等它做完才看：定期用 `glob`／`grep`／`read` 確認檔案真的在長。
3. 有背景 job 時用 `job_output` 收輸出；不再需要的 job 用 `job_kill` 收掉。
4. 一旦發現方向錯了（改錯檔案、做錯需求），**立刻** `send_message` 或 `interrupt_agent` 攔下來，不要等它做完。

### 4. 獨立驗收（最重要）
- 讀 diff：`git status --short`、`git diff`（或讀檔）。
- 跑驗收條件：在專案資料夾用 `pwsh` 執行卡上的指令，貼出真實輸出。
- 對照規格：逐條勾 `docs/01-需求規格.md` 的驗收標準，未通過的不要打勾。
- 邊界測試：空白輸入、錯誤輸入、重開程式後資料還在嗎。
- 把驗收證據填進 `docs/04-進度日誌.md`。

### 5. 失敗處理
- 重派時**附上失敗輸出**與你判斷的原因、以及要它改變什麼。
- 不要說「再做一次」；要說「上次 X 錯誤，改成 Y」。
- 連續失敗達上限 → 用 `ask_user_question` 給使用者 2 個選項：降低範圍（推薦）／換做法。

### 6. 回報使用者（三句白話）
已完成：<白話>；
證據：<我跑了什麼、看到什麼>；
下一步：<存檔並繼續下一個里程碑>。

## subagent 任務 prompt 模板
```
你是實作工程師。你只能看到這則訊息，看不到母對話。

【專案】<名稱>，位於 <絕對路徑>
【目標】<一句話>
【背景】現有檔案：<清單與用途>；已使用的套件：<清單>；前一步已完成：<什麼>
【寫入範圍】只能修改：<路徑清單>。範圍外一律不要動，也不要新增檔案除非在範圍內。
【具體要求】
1. ……
2. ……
【驗收條件】執行 `<指令>` 應得到 `<預期輸出>`；<檔案> 應符合 <規格條號>
【限制】不要安裝新套件、不要改資料格式、不要寫與本任務無關的註解或文件。
【回報格式】
1. 做了什麼（3 行內）
2. 改了哪些檔案（完整路徑）
3. 怎麼驗證（貼出你實際執行的指令與輸出）
4. 殘留問題或你不確定的地方
```

## 完成檢核
- [ ] 每個 subagent 的任務卡都自足（無隱含前提）
- [ ] 每個成果都有我親自跑出的驗證輸出（不是轉述）
- [ ] 規格驗收標準逐條對照過
- [ ] 沒有任何範圍外的檔案被我或 subagent 改動
- [ ] 使用者收到三句白話回報
