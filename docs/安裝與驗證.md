# 安裝與驗證紀錄

- 版本：v1.1（跨機器可安裝）
- 日期：2026-10-01（v1.0）、2026-10-02（v1.1）
- 執行環境：Windows 10、**Windows PowerShell 5.1**（本機沒有 `pwsh` 7）、Git Bash（`C:\Program Files\Git\bin\bash.exe`）、
  node v24.13.0、git 2.31.1
- harness：桌面版 **dsh 0.2.0-rc.2**（profile `web`）

---

## 0. 前置條件

1. **session 權限必須是 `danger-full-access`**（PM 要跑 `git` 等指令）。
   本機的 DSH 工作區上，`workspace-write` 沙箱會因為無法授與 ACL
   （`SetNamedSecurityInfoW failed (Win32 5)`）而使 `pwsh` 工具整個失敗——連 `Get-ChildItem` 都跑不動；
   同一個指令在 `danger-full-access` 下正常。
2. 有一個 DSH home（`$DSH_HOME` 或 `~/.dsh`），且裡面至少一個 profile 含 `cordis.patch.yml`。

---

## 1. 安裝（跨平台）

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

```bash
# macOS / Linux / Git Bash
bash scripts/install.sh
bash scripts/verify.sh
```

可選參數：Windows `-DshHome DIR -Profile NAME`；其他 `--dsh-home DIR --profile NAME`。
安裝前想留基準：`verify.ps1 -Snapshot` / `verify.sh -Snapshot`。

安裝只動兩個地方：

| 位置 | 動作 |
|---|---|
| `<DSH_HOME>/profiles/<profile>/cordis.patch.yml` | 插入／更新 marker 區塊（寫入前備份 `…bak-pm-<時間>`） |
| `<DSH_HOME>/pm-mode/` | 放 `skills/`（六份 `pm-*`）與 `install.json`（manifest） |

## 2b. v1.3：為什麼重啟後看不到模式（實際事故與修正）

**現象**：使用者完整重啟 DSH 桌面版後，開新 session 仍看不到「DSH PM 模式」。

**診斷**（用執行期探測，不猜）：

1. `~/.dsh/profiles/` 底下有 **`desktop`**、`web`、`headless` 三個 profile。
   - `desktop`：41 行、1.2 KB；bundle = `dsh-base`、`dsh-web-app`、agent-team-profile、auto-review、schedule、voice-input。
   - `web`：792 行、29.6 KB；多了使用者自己裝的 `@linxin666/dsh-web-all`（task-board／git-graph／preset-center／liangshen…）等。
2. 查執行中的 host（`cordis_inspect_query` → host `Config` → `listConfigs`）：
   樹裡有 `include:preset-standard`、`preset-ptc`、`preset-minimal`、`preset-cordis`，**唯獨沒有 `preset-pm`**；
   而且所有 id 帶 `include:` 前綴、完全沒有 `web-ui-*` 那些行。
3. `dsh --profile desktop --dump-config` → `error: profile "desktop" is managed exclusively by the Electron application`。

**結論**：桌面版載入的是 `desktop` profile，而 v1.2 只把 preset 裝進 `web` → 自然看不到。

**修正（v1.3）**：安裝器改為預設安裝到**所有支援 agent preset 的 profile**
（`package.json` 的 bundle 含 `dsh-web-app` 者；`headless` 自動略過），`verify`／`uninstall` 同步逐 profile 處理。

**修正後的多 profile 測試**（假 DSH home + 真實三份 profile 複本）：

| 測試 | 平台 | 結果 |
|---|---|---|
| 目標解析 | PowerShell | ✅ `profiles : desktop, web`（`headless` 正確略過） |
| 安裝 | PowerShell | ✅ 兩個 profile 都 `已追加新區塊（marker 1 組）` |
| 驗證 | PowerShell | ✅ `全部檢查通過`（兩個 profile 的 marker／id／路徑全 OK；skills／templates／manifest OK） |
| 移除 | PowerShell | ✅ 逐 profile 移除；`desktop`、`web`、`headless` 與原始檔**各 0 行差異** |
| 目標解析＋安裝＋驗證＋移除 | bash（Git Bash） | ✅ 同上，`全部檢查通過`、三個 profile 各 0 行差異 |
| 真機安裝 | PowerShell | ✅ `desktop` 與 `web` 都寫入；`verify` 全部檢查通過（`web` dump 差異 新增 221 行、移除 **0** 行；`desktop` dump 因 Electron 專屬管理而 `[WARN]`） |

**`desktop` profile 的驗證方式**：CLI 不能 compose 它，所以只能靠「重啟後開新 session 看選擇器」，
或用 `cordis_inspect_query` 查執行期組合樹是否出現 `preset-pm`。`verify` 對它的其他檢查（marker／id／skill 路徑）照常執行。

## 4. 驗收 4–8（待使用者動作）

| # | 驗收項 | 狀態 | 做法 |
|---|---|---|---|
| 4 | 模式出現在預設選擇器 | ⏳ | 完整重啟 DSH → 開新 session → 選「DSH PM 模式」 |
| 5 | 人設與名冊生效 | ⏳ | 該 session 的系統提示詞開頭應為 PM 人設；工具含 `subagent`、`workflow`、`ask_user_question`、`todo_write`、`plugin_manager`、`skill` |
| 6 | 6 個 `pm-*` skill 載入 | ⏳ | 該 session 的 skill 目錄應列出六個 |
| 7 | 端到端煙霧測試 | ⏳ | 見 §5 |
| 8 | 安全紀律 | ⏳ | 觀察破壞性／安裝動作是否先詢問 |

### 怎麼做（白話）

1. **完全關閉** DSH 桌面版（不是只重整網頁），重新打開。
2. 開一個**新的空白 session**，在預設選擇器找「**DSH PM 模式**」。
3. 選它，然後問：「你現在是什麼角色？請用一句話說明，並列出你有哪六個 pm-* skill。」
   - 預期：它說自己是使用者的專屬 DSH 專案經理，並列出六個 skill。
4. 若選擇器裡沒有 → 跑 `verify` 確認 patch，再確認是否真的完整重啟。
   （`dsh` 的 profile 設定有 HMR 監看，理論上新開 session 可能不用重啟；先試開新 session，沒看到再重啟。）

## 5. 端到端煙霧測試腳本（驗收 7–8）

在 workspace 底下開新 session 選 PM 模式，說：

> 我想要一個可以記錄每天花費的小工具，能看一個月總共花多少。

觀察並記錄：

- [ ] 訪談問題 ≤3 個、每題都有建議答案（`pm-intake`）
- [ ] 產出 `docs/01-需求規格.md`，並**先問你確認**才動工
- [ ] 你回「可以」後才建資料夾、`git init`、第一個 commit（`M0: …`）
- [ ] 派研究 subagent 並產出 `docs/02-技術研究.md`（含可點開來源）
- [ ] 產出 `docs/03-開發計畫.md`，里程碑對使用者有意義
- [ ] 派實作 subagent，PM 自己讀 diff／跑測試（不是只信 subagent 回報）
- [ ] 里程碑完成後 `git commit` ＋ `git tag m1`（`git log --oneline --decorate` 可見）
- [ ] 回報為三句白話（完成／證據／下一步）
- [ ] 若要求安裝插件 → 有先問你同意（驗收 8）

## 7. 安裝到別台電腦的流程（v1.1 目標）

1. 把整個 `dsh-pm-mode` 資料夾複製過去（含 `.git` 更好），放哪裡都行。
2. 用 DSH 在該資料夾開 session，說：**「請讀 README 並幫我安裝 dsh-pm-mode」**。
   - agent 會讀到 `AGENTS.md` 的 runbook（或 README 的同一份），自動判斷平台、跑安裝與驗證。
3. 驗證通過後，agent 會請使用者完整重啟 DSH，再開新 session 選「DSH PM 模式」。
4. 之後這個資料夾可以移動或刪除；要更新版本就覆蓋後再跑一次安裝。

## 8. 遇到的坑（已修正）

| 坑 | 現象 | 修正 |
|---|---|---|
| Windows PowerShell 5.1 讀 UTF-8 無 BOM 的 `.ps1` | 中文變亂碼 → `ParserError: 未預期的 'dump-config' 語彙基元` | 三個 `.ps1` 改存 **UTF-8 with BOM**；日後用外部工具改過 `.ps1` 後要重套 BOM |
| 本機沒有 `pwsh` 7 | `pwsh -File ...` 找不到指令 | 文件與腳本訊息改用 `.\scripts\xxx.ps1` 或 `powershell -ExecutionPolicy Bypass -File ...` |
| 沙箱 `workspace-write` 無法執行 shell | `SetNamedSecurityInfoW failed (Win32 5)` | 安裝與使用 PM 模式的 session 權限一律用 `danger-full-access` |
| bash 的 `diff` 拿 PowerShell 寫的 baseline 比對 | CRLF vs LF → 全檔誤判為差異 | bash 端比對前先 `tr -d '\357\273\277\r'` 正規化（同時處理 BOM 與 CRLF） |
| bash 把 MSYS 路徑（`/c/Users/…`）傳給 `dsh` 與 `node` | dump 用到錯的 home／node 讀不到檔案 → 誤判有行被移除 | 傳給 `dsh`、`node` 前一律先 `cygpath -m` 轉成 `C:/…`（`pm_render_path`） |
| 假 DSH home 被拿去跟真機 baseline 比 | 誤報「有行被移除」 | baseline 旁記錄 `.home`；home 不同只警告不比對 |
| 技能長度兩平台算法不同 | PowerShell 算 UTF-16 字元、bash 算位元組 | 兩邊統一用**位元組**（檔案大小） |
| preset 檔頭註解的佔位符也被取代 | 註解出現機器路徑，語意錯誤 | 檔頭改寫成「技能目錄佔位符」，整檔只剩一處真正的佔位符 |
